## Required changes (exact list)

1. **Stop false `form_validation` rejects** (`src/runtime-attribution-browser.js:480-489`, rebuild dist). Record `form_invalid` only for a click/Enter dispatch that the browser would validate: `!form.noValidate`, and the submitter has no `formnovalidate`. Never record it on a `submit` dispatch, because a submit event means validation passed or was bypassed. Better: count it as a reject only when no `submit` event followed in the episode. Add the `formnovalidate` and `noValidate`-multi-step probes to the driver. Both must print `no_request`.
2. **One label per action_id on every surface.** The export (`buildActionChains`, `runtime-attribution.mjs:720-738`) must either carry the episode's outcome, computed from the same credited request as `buildEpisodeChain`, or name its per-action scope in a distinct field. With a field named `outcome`, it must never contradict `action_chain.outcome` for the same action_id (today it does on 300/408 G6 actions, 2/54 final7, 11/25 of the driver store, and the probe click `:35`). Add a check over **all** action kinds (focusin, keydown, input, change) to the driver.
3. **Mixed statuses must be stated.** When an action's requests include a ≥400 that is not the credited request, `label`, `sentence`, `chain.display.label`/`terminal.label`, the export and `outcomeText` must say so (e.g. `Completed 201: insert items; 1 other request failed (500 POST /api/reports)`). The G4 amendment must state which request decides the status and why.
4. **`compare_chains`**: add `status` (and `reason` for rejects) to `outcome_delta.changed`. Never print "outcome unchanged" when `before.outcome !== after.outcome`. Correct the RUN.md justification (the G6 verdicts are unaffected).
5. **Request-bearing brackets never print a validation word next to a response.** Keep `also handler_threw/promise_rejected (Type)` if wanted. Drop `form_validation` from `also` (and de-duplicate), so `completed 201; also form_validation, form_validation` cannot appear.
6. **Evidence**: add `store/records.jsonl.gz`, `spans.jsonl.gz` and `runs.jsonl.gz` (with sha256 and row counts in an `ERRATA.md`, not by editing RUN.md). Correct RUN.md's claims through an ERRATA: rethrow location for non-Error values (3a), and the scope of unseen rejections (2j). Make the claim text and the gate agree on 3xx (2a').

Recommended, not blocking: mark a read-only terminal join in the label (e.g. `Completed 200: find seats (read only)`), or reserve `completed` for non-GET requests with a write. Otherwise an agent told that `completed` means success will call a POST that only read a success.

## Residual risks (after the changes)

- Server span status is trusted as the response. A socket destroyed before responding records 200 (2e'). The browser records no response status to cross-check it.
- Followed redirects always abstain at network (two exact-parent server spans).
- `handler_threw` misses thrown primitives and errors that never pass through an instrumented `catch` (2d, 2j). The fallback is `no_request`, which abstains but understates a crash that `function.exit.threw` did record.
- Error identity is keyed to the **first** owning action (`src/runtime-attribution-browser.js` `threw`). An error object cached by the app and rethrown later from another action is reported against the first action.
- The G5 same-form-mutation rule (`submit.rejected`) still labels a request-less multi-step "Next" whose step 2 renders in the same form as rejected (RUN.md residual 1). Change 1 does not fix that path.
- React 19 (`reportError`) and dev builds were not run.
