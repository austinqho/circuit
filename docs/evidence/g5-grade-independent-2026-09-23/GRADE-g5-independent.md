### Residuals (none blocks merge)

1. **Trailing form actions with no effect lose their episode.** A new edge case in the shared indexer. After the last request-bearing submit, a trailing segment with no request, no mutation and no submit gets no episode (`if (!effectful.length && !submits.length) return;`). Its actions stay `claimed`, so they become `episode:standalone:*`. I confirmed this over the MCP on a four-row synthetic store: three keystrokes after the last save are three standalone episodes. `element_history({input key, n:2})` then returns two single-keystroke "attempts" and pushes both real attempts out. Main kept such keystrokes in the form episode. It does not occur in the c, G6 or final7 stores, where every form action is in a form episode. It will occur whenever a user types after saving without a DOM change. Fix: attach an effect-less trailing segment to the preceding segment, or give it its own form episode.
2. **The episode rule now changes chains beyond repeated submits** (R1c). This improves the answer on G6's create-workspace submit, but the gate text (§10 D-G5-2, "Episodes with fewer than two such submits keep their id and content") describes the old store-only rule. The M1 viewer's cards change with it. Record this in the gate doc.
3. **The collector accepts any origin** (`access-control-allow-origin: *`, pre-existing). It now also has `POST /run-info`, which any page the developer visits could use to overwrite the run row's `source`/`steps`. It is loopback-bound, so the risk is low. A token or an `Origin` check would close it.
4. A root-relative `collector` path is accepted without `allowRemote`. It resolves to the page's own origin (a LAN dev server stays reachable). This is acceptable because production builds drop the sink unless `force`.
5. Still out of scope and unproven: Codex's real anchor builder, the live-DOM uniqueness of the selector (it rests on the recorded native count), and Part B.
