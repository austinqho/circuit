# G6 evidence errata (added after the evidence commit; the original files are unchanged)

1. **RUN.md, first paragraph, commit order.** RUN.md says the harness `--store` wiring and the `compare_chains` detail wording were "committed together with this directory". That is wrong. They were committed one commit earlier, in `17cc3261` ("G6: harness --store wiring, scenario compare driver, independent grader"). The evidence directory itself is in `9279dd3f`. The code that produced the runs is `accab8bf` plus the working-tree harness change later committed as `17cc3261`. The only thing that differed at run time is the wording of the `source_revision` `detail` string. The runs produced `ordinal N of M`; `17cc3261` changed it to the 1-based "pre-order position". The `compare/*.json` files were regenerated after that wording change, so they show the `17cc3261` wording.
2. **Stored manifests keep a bundle-local `index`.** `store/manifests/*.json.gz` still carry each manifest row's runtime `index`, taken from the first run of that build (A for `b-2dc9ecff4d63b25e`, D for `b-a33d446fe91e8701`, E for `b-492209beb3a2e901`). Runs B, C and C-fix-r2 share A's build id but numbered the same functions differently (4,828 / 4,857 / 4,909 of 5,101 positions differ from A). The store writer was changed afterwards (`17cc3261`) to drop `index`. Nothing in the store reader, the MCP or the grader reads `index`, because rows join by `function_id`. LIMITS.md item 6 already records this; this entry makes it an erratum.
3. **`change_basis: "manifest_remap"` in `compare/*.json` is the pre-amendment vocabulary.** After this evidence was written, the coordinator asked the remap to try, in order: whitespace-normalised text match, then name match, then ordinal. The result now reports which basis matched (`text_match | name_match | ordinal | unmapped`). The stored manifests here carry no text hash or name, so today's code resolves these pairs with `ordinal`, the same rule that produced `manifest_remap` here. A supplementary rerun with manifests enriched from the fixture commits is in `../g6-anything-llm-2026-09-23-remap-bases/`, if present.

## Additions after the independent grade (`../g6-grade-independent-2026-09-23/GRADE-g6-independent.md`)

4. **Manifest index differences are position counts, not per-function counts.** LIMITS.md item 6, ERRATA item 2 and the gate doc §3.1 say that 4,828 / 4,857 / 4,909 of 5,101 positions differ from A for runs B / C-fix / C-fix-r2. Those numbers compare `index` at the same *array position* of the two manifest files, so they mix array reordering with renumbering. Counted by function id (the same function with a different `index`), the numbers are **4,139 / 4,563 / 4,458**. The conclusion stands: `index` is bundle-local and no reader keys on it.
5. **Handler names.** The gate doc §2 names the route's handlers "`validatedRequest`, `flexUserRoleValid`, and the anonymous update handler". The spans record `#0 validatedRequest`, `#1 <anonymous>`, `#2 <anonymous>`. `flexUserRoleValid([...])` returns an unnamed closure, and the chain never shows the name `flexUserRoleValid`. Because handler stops compare `(route, index) → name`, two `<anonymous>` handlers compare equal whatever their bodies. That is why seed B shows only as a status change (LIMITS.md item 1).
6. **Run C: "the chained harness run went ahead" is inference.** RUN.md ("Operator error") says the revert failed and "the chained harness run went ahead at the seed commit". The files support three facts: `git revert … -q` prints usage and exits 129; the fixture reflog has no entry between `8bc8ae7` and `719f176`; and the `C-fix` run's `source.commit` is `8bc8ae75`. The files do not show how the harness invocation was chained to the revert. The account of *why* the run proceeded is the operator's recollection, not recorded evidence.
