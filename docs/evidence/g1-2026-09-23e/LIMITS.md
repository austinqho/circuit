# Limits (g1-2026-09-23e)

- **Grading.** Headless Chromium only. Checks were done by script: `g1-grade.mjs`, `g1-chains.mjs`, `g1-unattributed.mjs` and raw-row recomputation with python. I read Mongo directly with `mongosh`. No independent grader has reviewed this directory.
- **Recall gap (unattributed requests, 39 per run).** The receipt rule abstains when React work is triggered on the scheduler without a receipt on the fibers that fetch: the post-login batch, the queries after agent create, and refetches after a stream ends. These are listed with reasons, not credited. Round three's lower count (25) came partly from the run-time ambient inheritance this pass removes.
- **D-G1-15 is a guard added in this pass, beyond the coordinator's rule.** Renders never inherit; unreceipted effects keep only a direct, non-bare, non-scheduler continuation; React's delegated listeners are never owned.
  - Without it, the creation-time rule let React's scheduler message carry whichever action posted it, and a portal listener registered there misattributed the delete flow (`superseded-999deea4/frontend-only`).
  - Detecting React's own listeners uses React-internal property names (`_reactListening…`, `__reactEvents$…`); the render test uses the hooks-dispatcher shape. Both are React 18 internals.
- **Layout effects** are now wrapped through the dispatcher hook (`useLayoutEffect` / `useInsertionEffect`). Class lifecycles and ref callbacks run during the commit on whatever continuation the commit is flushed on, and are not wrapped.
- **Listener ownership keeps the first owner.** A listener added under an action is re-registered by identity. Adding the same function again under a later action keeps the first owner, which is the browser's de-duplication. A `once` listener is wrapped anew each time.
- **Native suspensions.** Async generators and `for await` still suspend natively, as the explicit frontier. A continuation left current by such a suspension is cleared at the end of the next task callback (`task_ambient_cleared` counts this; it was 0 in the neutral runs).
- **Nondeterminism.** The two LibreChat runs differ by one unattributed request each way: a `GET /api/permissions/agent/:id` credited `mount_effect` in one run, and one extra `GET /api/balance` in the other.
- **Feedback** still does not write with the deterministic chat fixture (placeholder message id). This is a harness limit, as in rounds three and four. The grader's telemetry-on `pass` is false for that reason alone.
- **Parity gate.** Two `m1-live.sh start` attempts failed parity on the default model name because the parity backend runs without the chat fixture. The third attempt passed. I did not change the gate.
