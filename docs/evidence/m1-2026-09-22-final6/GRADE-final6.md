## 7. Final assessment

What final6 proves: the capture is lossless on the raw evidence (647,573 rows across 25 record-bearing pages, every page's sequence contiguous, every first-party request stamped, 1,017/1,017 server spans and 4,164/4,164 db spans joining by exact trace id and W3C parent — the final5 late-boot loss is closed); every Mongo write for the user in the window (32 timestamped rows plus the login session and 24 boot rotations) is owned by its causing `dom.action` with no bystander and no silent write; all eight gate flows reach a real write, including agent-create (`POST /api/agents` → `agents.insert` matching Mongo to the millisecond) and agent-chat (`POST /api/agents/chat/agents`); and the D24 redefinition did what it promised at the level it was specified — 195/195 credited actions credit exactly the first depth-zero frame, no action is credited to two units, the bystander `reached_db` credits of final5 (Convo focus, Convo row click) are now spine-only, and 0 of 14 write-bearing actions are uncredited (was 8). What remains: D24 identifies "first depth-zero first-party frame" with "entry handler", and the run shows those are different things — 3 of 14 write-bearing actions (login, edit-resubmit, agent-create) and 21 of the 72 "inventory gaps" credit a react-hook-form validator, a Recoil callback factory, a hook, a getter, a render prop or a react-spring callback, because the real handler was either library code (Ariakit/Radix/RHF `register`) or, in the edit-resubmit case, registered but never entered; two more credits go to window-level capture listeners. The static side is also short: roughly two thirds of the 72 gaps are bindings the analyzer should have produced (call-wrapped `handleSubmit(cb)`, handlers passed as props through `HoverButton`/`Button`/`TooltipAnchor`, Ariakit and Radix props without contracts, intrinsic buttons under uncontracted custom children) or should have joined (React `onChange`/`onBlur` vs native `input`/`change`). Mutation observation still does not cover the scripted flows, and 16 states are `not_reached` while the stop counter reads 0. Honest coverage on the runtime denominator: **94 driven entry-handler units against an estimated ≈690 registered handler bindings rendered on visited states (range 375–700) — about 14%, and about 10% (71/690) if only credits that are actually handlers count**; the bundle's 22/343 (6.4%) and 22/65 (33.8%) are both wrong denominators, the first because it omits 72 executed handlers, the second because it counts only what the fiber walk could stamp. The single most valuable next fix, with evidence: change the entry-handler rule from "first depth-zero first-party frame" to "first-party frame invoked directly by the event dispatch, before any React render flush" — i.e. record the caller boundary (event plugin / DOM listener vs render/commit) on `function.enter`, skip frames entered while React is rendering, and treat validator frames run by `handleSubmit` before `onValid` as spine. Evidence: under `mud5gdh4:29` the real `AgentPanel.tsx:13140:14819` `onSubmit` entered at depth 0 six sequence numbers after the credited validator; under `mud5esjd:6` `LoginForm.tsx:3870:3894` entered at seq 67 after the validator at seq 15; under `mud5gcsb:22` the credited `useLiveAnnouncer` is followed by 3,205 depth-0 render frames of `ModelPanel.tsx`; and 23 of 72 gap credits disappear under that rule, which would also convert `LoginForm.tsx:3870:3894|submit` from `not_encountered` to `reached_db`. The complementary static fix — resolving `handleSubmit(cb)`, curried factories and prop-passed handlers through first-party wrappers, and keying the join on the React prop name rather than the native event — would then recover ChatForm submit, Feedback, EditMessage resubmit, AgentPanel and HoverButtons as inventory units, which is where the core interaction patterns actually live.
