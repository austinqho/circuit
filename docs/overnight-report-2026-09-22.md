## Definition of done (the final test)

1. Codex derives the interaction-pattern inventory of LibreChat from Tracer's own control inventory (not from a hand list), clusters it into patterns (send, copy, edit-resubmit, regenerate, feedback, rename, delete, archive, pin, share, duplicate, fork, bookmark/tag, project create/move, agent create/edit/chat, memory create/edit, prompt create, settings toggles, model/endpoint switch, file attach, search, export, navigation between conversations, keyboard shortcuts, sidebar toggles, and whatever else the inventory shows), and drives every pattern headless with trusted clicks.
2. For every pattern, Tracer emits a chain record: click → first-party handlers → library edges → request → route → handler → DB op, or an explicit stop with a reason. No pattern is silent.
3. The grader confirms, per pattern, that the record's ids (conversation, message, parent, agent, user) match Mongo by string equality, that backend effects are witnessed by spans on the same trace, and that overlapping actions are not cross-attributed. Silent gaps and wrong ids are both failures.
4. The bus-stop viewer (fiber-demo) renders each pattern's chain, one screenshot per pattern, as the human exhibit.

Rules carried through every instruction: read-only to LibreChat's tracked source; no LibreChat-specific rules in the package; no model calls in the runtime path; headless only; commit as you go; prefer end-to-end runs over unit tests; report stops as stops.

## Loop protocol

Each cycle: (a) Codex run ends → (b) inspect branch, evidence, raw records → (c) grader subagent scores against Mongo → (d) decision written below with cause and why the fix is robust → (e) resume the thread with one instruction → repeat.
