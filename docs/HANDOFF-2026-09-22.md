## 1. What Tracer is, in one paragraph

Tracer (npm package `producttrace`, GitHub `austinqho/tracer`) attaches to a React app read-only at build and load time, records every user action losslessly, follows each action through first-party code, library boundaries, requests, Express handlers and MongoDB operations by identifier only, and renders each action as a bus-stop path a non-engineer can read. Target consumers: Trajectory (continual-learning SDK: `trace_id`, `properties.attached_message_id`), PostHog as a destination, the user's own Chat/Logs workspace later. The wedge versus PostHog, proven by experiment on 2026-09-20 (`docs/evidence/`-adjacent: `/Users/austinho/dev/trace-consolidated/.live-demo/librechat-posthog-opus/GRADE.md`): PostHog's wizard met one of five criteria; reaching the id-grounded action log took an expert agent editing 23 LibreChat source files, with degraded generation telemetry and unflagged defects. Tracer produces that record without touching source. Vision language from Austin: "two tabs: chat and logs", "everyone gets their own sandbox", "make the product weld itself to the user", "Telemetry 2.0 is include all", "noise is signal if you ground it". Strategy doc: `docs/posthog-differentiation-reference.md`.

Naming lineage (folders you will see): retrace → Producttrace (`~/dev/trace-archive/repositories/Producttrace`) → product-telemetry → trace-consolidated (`~/dev/trace-consolidated`, frozen experimental tree; freeze bundle `~/dev/producttrace-freeze-2026-09-07`) → tracer (`~/dev/tracer`, this repo). "Astra" was a parallel frontier-model workspace, not a product.

## 3. What works now (branch `m1-runtime-attribution`, 184 commits ahead of `origin/main`, unmerged, tree clean)

Engine (the M1 gate), graded against Mongo by an independent agent:
- Read-only attach: Vite plugin instruments after Vite's TS/JSX transform with position-preserving edits and integer manifest ids (`integrations/runtime-attribution.mjs`, `integrations/vite.mjs`); LibreChat's tracked source stays byte-identical; build gates refuse to serve if markers ≠ manifest (9,663/9,663 on the last build) or if the Agent Builder differs between plugin-disabled and enabled builds (parity gate).
- Lossless capture: per-page sequence numbers, acknowledged batches over fetch keepalive, pagehide beacon flush, collector verifies contiguity; full sessions at 647,573 = 647,573 rows, 0 gaps.
- Every request seen: fetch/XHR/EventSource wrappers installed before app code; gate "wrapper-recorded == Playwright-observed, 0 reconciliation" (1,110/1,110 on final6; note the late-boot snapshot defect in D24 is fixed).
- Continuation-carried action context (promises, timers, microtasks, streams, React scheduling), `linkage_kind` direct vs mount_effect, negative test that a pre-armed poll timer is not attributed.
- Exact joins only: browser request span → server span (same trace, exact parent, method) → registered-handler callback span → DB span as descendant; same-URL or nearby-time never joins; Mongo `findAndModify` collection normalized from the command key; no statement text retained. Final6 grade: 1,017/1,017 server spans and 4,164/4,164 DB spans joined, zero false joins, every Mongo write in the window owned by its causing action.
- O(actions) records: per action, `dom.action`, `function.enter/exit` only for functions on the action's continuation lineage (with `invoked_by: event|render|effect|async`), requests, `dom.mutation` receipts, joins; 796k rows became 1,791 for the same ten-step session; raw all-functions mode is a debug flag.
- Effect-rooted entry handler (D24–D27): the unit of an action is the depth-zero first-party frame whose continuation contains the action's effect (request, or DOM mutation); validators, announcers, getters are spine. - Eight LibreChat mutation flows Mongo-confirmed to the millisecond through the drive: send, thumbs-down feedback, regenerate, edit-and-resubmit, rename, agent create (`POST /api/agents` → `agents.insert`), agent chat (`/api/agents/chat/agents`), delete.
