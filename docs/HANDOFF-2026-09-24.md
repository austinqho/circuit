## 1. What Tracer is, in the owner's words, and the doctrine

Tracer (npm `producttrace`) attaches to a React app read-only at build time with one Vite plugin line, records every user action losslessly, follows each action by identifier through first-party code, requests, Express handlers and MongoDB operations, and renders each action as a bus-stop path an agent or a non-engineer can read. The wedge versus PostHog, proven by experiment on 2026-09-20: PostHog's wizard met one of five criteria; reaching an id-grounded action log took an expert agent editing 23 source files. Tracer produces that record without touching source.

Austin's phrases that still steer everything: "read only to source but not to runtime"; "tied to specific ai output id's"; "Telemetry 2.0 is include all"; "noise is signal if you ground it"; "abstain over guess"; "two tabs: chat and logs" (the interface, deferred); "make the product weld itself to the user". On process: "the executor never grades itself"; "robust fix, not a temporary bandage; write why"; "avoid unnecessary unit tests, run more e2e tests"; "do NOT build another headless crawler"; "headless only, never my screen".

Doctrine (binding, every gate applied it): identifiers attach, timestamps only order; abstain over guess; capture wide, never silently drop; explicit frontiers ("reached / stopped at / because", never "mapped"); no model in the runtime path; no app-specific rules in the package (the harness may know the app); one claim per PR; gate text before code; evidence directories immutable (add files, never edit); independent grader for every claim, recomputing from raw rows; headless only.

The 2026-09-23 pivot (Austin's handoff) reordered priorities: for now Tracer is a dev tool for coding agents ("installable on any Vite + React repo, queryable by agents through MCP, packaged as a Codex plugin"), because OpenAI has built, and not yet enabled, a page-to-agent annotation channel in its desktop in-app browser whose payload can carry a pointer but not a history. Tracer is what the pointer resolves to. The M1 engine is the foundation; M2 (identity from types) is next after this cycle.

## 4. The engine rules as they stand (read this before changing attribution)

### 4.1 Action context (G1 rounds four to six, PR5)

- **Creation-time ownership, strict frame stack.** A continuation created while an action frame is current (promise `then`, native `await` via the rewrite, `queueMicrotask`, timers armed now, `MessageChannel.postMessage` sent now, `requestAnimationFrame`, listeners added now) captures that frame, bare or not. A callback created before the action captures nothing from it. At run time there is no ambient fallback (`ownerFrame = owner`, never `owner || previous`). Every frame exit restores exactly the frame current at entry (the round-four leak was a nested focusin frame that never popped, leaving a handler frame ambient for 14,392 later calls).
- **Native `await`** is rewritten so resumption (fulfilment and rejection paths) restores the frame current at the await. This changes microtask interleaving relative to native (`baca2d` vs `aba2cd`), disclosed.
- **State-update receipts.** Setters wrapped through the React dispatcher (16–18 `.current`, 19 `.H`, found from the renderer's version on the DevTools hook; otherwise one `capture.limit {feature: "state_receipts"}` per page and receipts abstain). One receipt per (action, fiber), consumed by the first commit after it, attributing that commit's work for the fiber only if the fiber rendered AND a receipted hook's rendered state changed by `Object.is` versus the value captured at the call (function updaters included; no-op updates never attribute). Mount effects of fibers newly mounted inside the receipted subtree inherit as `mount_effect`; the receipted fiber's own passive effects are `state_effect`. Renders never inherit; an unreceipted effect keeps only a direct, non-bare, non-scheduler context; React's delegated listeners are never owned (React-18-internal name detection, recheck per React major).
- **Bare dispatch frames** are inheritable at creation time (form libraries await before calling the app's handler) but never at run time.
- **Listeners (PR5).** A listener invoked by a trusted UI event runs under the live trusted dispatch on its synchronous stack, else under no action, never its registration owner; a programmatic event runs under whatever called `dispatchEvent`; non-UI trusted events (XHR, WebSocket, `load`, `message`) keep registration ownership.
- **Entry-handler credit (effect-rooted).** The credited handler is the depth-zero first-party frame whose continuation owns the action's terminal evidence; validators, announcers and getters are spine. In code this is the browser's `terminal_owner_continuation_id`, chosen by `entry_hint` priority (the transform marks call-argument and `onX`-prop functions), because the continuation graph still does not cross an await for the purpose of `descendsFrom`. Disclosed in G1; not a false credit in any graded run, but it is a heuristic, not the graph.
- **Abstention.** If the credited frame is not bound to the target's fiber chain (React `on*` props, first-party `addEventListener` on the target or an ancestor, listeners inside shadow roots) and owns no request, the chain stops at `stopped_at: "entry_handler"` listing the global listeners.
- **Requests** are recorded by the runtime's own fetch/XHR wrappers (bridge off); every row carries a traceparent; joins are exact trace id + parent span id, no URL or time similarity, ever.

### 4.2 Episodes (G5, PR4)

One implementation, `indexWorkflowEpisodes`. A form episode contains field events and submit-capable actions on that form; it closes at each submit that sent a request (repeated submits are separate attempts); trailing no-effect keystrokes join the form's latest episode; focus folds into the next action on the same control within 1000 ms; everything else is standalone. Never two controls in one episode. `element_history`'s `n` counts attempts.

### 4.3 Frontier vocabulary (PR1, PR6)

`reached`: how far the evidence got (`dispatch`, `dom_mutation`, `entry_handler`, `network`, `route`, `handler`, `db`, `worker`). `stopped_at`: `browser` (scoped absence sentence), `validation` (rejected submit), `entry_handler` (abstention), `network` ("backend not instrumented" or "no span on trace"), `handler` (e.g. "server responded 422; no database span descends from the admitted handler span"), `worker`, or `none` when the terminal effect was observed. `unlinked` lists what was seen but not linked. `coverage` says whether the page's rows are provably complete. Outcomes: `completed` (2xx + terminal join), `responded` (2xx, no effect evidence), `failed` (≥ 400), `rejected_client_side`.

### 4.4 Element keys and stamps (G3, PR3)

`data-tracer-el` on every React-rendered interactive host (and inside open shadow roots). Key = placement id (file hash + span) + `@<react key path>` or `#n<ordinal>`. `element.stamp` rows carry file/line/start/end/component/handlers/url/build/`binding_placement`/`key_kind`/`instances`/`content_sig`/`commit`. Stamps are lookup keys for agents, never inputs to attribution (D12 test: records byte-identical with stamps on, stripped, off). `resolve_element` says `exact` only for a React-keyed key, or an ordinal key with one instance, whose content has not changed between the actions in scope or since. OAI attributes (`oai-annotatable`, `oai-annotation-metadata`, ≤ 6 flat entries, validated) are written only when `document.oai.annotation.request` exists or `oaiAttributes: 'always'` (dev).

## 5. Lessons (the ones that cost time)

## 8. Orchestration method that worked

Regrades are short and targeted. When an agent stalls, verify the process table before believing it, then start a fresh agent with a compact brief pointing at the committed state.
